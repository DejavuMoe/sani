# 统计口径

<p class="lead">Sani 的统计刻意做得很少：它回答“这条链接有没有人点、什么时候点、从哪里来”，而不去追踪点击的人。这一页说明每个数字是怎么来的。</p>

## 记录了什么

每条链接：

- **总点击数**和**最近一次访问的时间**；
- **每日点击数**，按服务器时区划分日期；
- **来源网站**：只记录 `Referer` 请求头里的域名（去掉 `www.`），不记录完整地址。没有 `Referer` 的访问记为“直接访问”。

整体：链接总数、全部链接的总点击、今天的点击，以及最近 30 天每天的点击。

## 没有记录什么

访问者的 IP 地址、User-Agent、完整的来源地址，以及每一次访问发生的时间，都不会保存。Sani 也不会给访问者设置 Cookie。数据库里只有聚合后的计数，没有逐条的访问记录，所以既没有访客隐私数据需要保护，数据库也不会随着访问量增长。

## 什么算一次点击 {#counted}

一次点击，是指有人在浏览器里打开了短链接。下面这些请求照常跳转，但不计数：

- `HEAD` 请求，以及浏览器的预取和预渲染（带 `Sec-Purpose` 或 `Purpose: prefetch` 请求头）；
- 搜索引擎爬虫、社交软件和聊天软件的链接预览、监控服务、无头浏览器；
- 命令行工具和 HTTP 库，比如 curl、wget、Python、Go、Java、Node.js 的请求；
- 没有 User-Agent 的请求；
- 从 Sani 管理界面里点开的链接，这样你自己测试不会影响数字；
- Sani 自己抓取标题时发出的请求（比如一条短链接指向了另一个 Sani 实例）。

识别爬虫和预览靠的是 User-Agent 里的关键词，比如 `bot`、`spider`、`crawl`、`preview`、`facebookexternalhit`。完整列表在 `internal/server/redirect.go` 里。

## 文本和文件 {#shares}

对[文本和文件](./usage#shares)来说，一次访问是有人拿到了内容。规则和上面一样，只有一处不同：

- **文本**：打开 `/p/{短码}` 页面算一次；从文件域名获取原始文本或下载，每次也各算一次。
- **文件**：从文件域名下载时才算，打开页面不算；详情里这一项叫“下载”。
- **在文件域名上，curl 和 wget 计入访问**：人们本来就常用它们下载文件，所以在这里把它们当作访问者；爬虫、预览、预取和 `HEAD` 请求仍然不算。每个成功返回内容的 `200` 或 `206` GET 请求都计一次，包括后续分段和后缀 Range；`304`、`412`、`416` 和读取文件失败不扣次数。成功响应开始发送后即计数，网络中断不会退回次数，也不代表客户端已保存完整文件。

原始文本和下载的来源通常是“直接访问”，因为分享页面不会发送 `Referer`。

## 访问上限怎么算 {#visit-limits}

设置了访问上限的链接，只有计入统计的访问才占用次数，爬虫和链接预览不会把次数用掉。次数用完之后，所有请求（包括不计数的）都会看到 410 页面。

同一链接的并发请求和缓存替换共享一个原子计数，因此单个运行实例在达到上限时停止放行。爬虫识别依赖可伪造的请求头，访问上限是统计规则，不是鉴权或保密措施；不要用它保护秘密。不要让多个写入实例共享同一个数据目录。

对文本来说，打开页面和获取原始文本是两次访问：访问上限为 1 的文本可以在页面上读到，但之后再点“原始文本”会得到 410。访问上限为 3 的文件可以下载 3 次；已经有 32 个下载在进行时，新的下载会先被 503 拒绝，不会占用次数。

## 数字有多及时

点击先在内存里累加，通常每 2 秒合并写入一次。链接总数值读取活跃计数器或已提交的数据库快照，不会把同一批点击重复相加；列表的小图、每日统计、来源和最近访问时间读取已提交数据，可能稍有滞后。详情统计、概览和导出会先尝试刷盘；写入失败会记录日志，响应中的统计可能仍是旧值。并发访问期间，不同接口或多个查询的结果不保证来自同一时刻。

正常停止会在有限时间内尝试写完剩余点击，失败以非零退出码报告。持续写入失败后强制退出会丢失全部积压点击，断电还可能影响 SQLite WAL/NORMAL 下最近的已提交事务；2 秒是调度间隔，不是最大丢失窗口。详见[运维](./operations)。

## 时区

“今天”和每日统计按 Sani 进程的时区划分，也就是 `TZ` 环境变量。Docker 镜像不设置 `TZ` 时使用 UTC，所以部署时记得设置，比如 `TZ=Asia/Shanghai`。

数据库里保存的是日期而不是时刻。以后修改 `TZ`，已有的统计不会重新划分，新的点击按新的时区计入。

## 来源网站

- `Referer` 请求头由访问者的浏览器发送，任何人都可以伪造。为了防止有人用大量虚假来源撑大数据库，每条链接最多记录 200 个不同的来源网站，之后新出现的来源都计入“其他来源”。
- 很多应用和浏览器出于隐私原因不发送 `Referer`，从 HTTPS 页面跳到 HTTP 页面时也不会发送，所以“直接访问”经常是最大的一项，这很正常。
- 详情里显示排名前 8 的来源。占比的分母是记录过来源的全部点击；导入的历史点击没有来源信息，不在其中。

## 为什么点击数可能比预想的少

- **永久跳转会被缓存**：301 跳转会被浏览器缓存一天，这期间同一个浏览器的访问不会经过 Sani。需要准确计数的链接，请使用默认的临时跳转。
- **预览不计数**：把链接发到聊天软件或社交网站时，平台通常会先抓取一次来生成预览。常见平台的这类请求会被识别出来，不计入。
- **你自己的点击不计数**：从管理界面里点开的不算。

## 为什么没有更多统计

地理位置、设备、浏览器、UTM 汇总这些数据，都需要记录每一次访问的细节，这会让 Sani 变成一个需要认真对待隐私的访客追踪系统，也会让数据库随访问量不断增长。Sani 选择不做这些。真的需要时，可以在目标网页上使用你自己的分析工具：短链接会把 `utm_*` 这类查询参数原样带过去。
