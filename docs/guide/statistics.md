# 统计口径

<p class="lead">Sani 遵循极简且重隐私的统计原则：回答“链接是否被点击、何时被点击、来自何处”，而不追踪访客个体。本页阐述各项指标的计算逻辑。</p>

## 采集维度

单条链接维度：

- **总点击数** 与 **最后访问时间**；
- **每日点击数**（按服务端配置时区切分自然日）；
- **来源域名**：仅记录 `Referer` 请求头中的域名（自动剔除 `www.`），不记录完整 URL。未携带 `Referer` 则归入“直接访问”。

全局大盘维度：总链接数、全部链接累计点击、今日点击及近 30 天每日点击走势。

## 隐私与免记录范围

访客客户端 IP、User-Agent、来源页面完整 URL 及每次访问的绝对时间戳均不入库，亦不向客户端植入任何 Cookie。数据库仅维护聚合计数，不保留逐条请求日志，既杜绝访客隐私泄露隐患，又避免数据库体积随访问量线性膨胀。

## 有效点击判定规则 {#counted}

有效点击指真实用户通过浏览器发起的短链接访问。以下请求会正常执行重定向，但**不计入统计**：

- `HEAD` 请求，以及带有 `Sec-Purpose` 或 `Purpose: prefetch` 请求头的浏览器预取与预渲染；
- 搜索引擎爬虫、社交平台链接预览爬虫、自动化监控探针及无头浏览器；
- 命令行工具与通用 HTTP SDK（如 curl、wget、Python、Go、Java、Node.js 默认 Client）；
- 缺失 User-Agent 的异常请求；
- 在 Sani 后台管理界面中发起的点击（避免管理员自测污染数据）；
- Sani 服务端自身抓取标题与图标时触发的请求（如短链接嵌套重定向）。

爬虫与预览主要基于 User-Agent 特征词匹配（如 `bot`、`spider`、`crawl`、`preview`、`facebookexternalhit` 等，完整清单见 `internal/server/redirect.go`）。

## 文本与文件分享的统计差异 {#shares}

[文本与文件分享](./usage#shares)的访问定义为内容交付。基础规则与常规链接一致，特殊约定如下：

- **文本**：访问 `/p/{短码}` 页面计一次；通过独立文件域名请求“原始文本”或执行下载各计一次。
- **文件**：仅当从独立文件域名成功下载时计入；访问元数据引导页不计入。详情面板展示为“下载”。
- **文件域名的命令行工具计入**：开发者常用 curl 或 wget 下载文件，因此在文件域名下将其视为正常访客。爬虫、预览、预取与 `HEAD` 仍被排除。成功响应内容的 `200` 或 `206` GET 请求均计一次（含分段与后缀 Range 请求）；`304`、`412`、`416` 及底层读文件失败不扣减额度。响应一旦开始输出即执行计数，后续网络中断不回退，亦不代表客户端已完整保存。

“原始文本”和下载请求由于跨站不带 Referer，来源统一归为“直接访问”。

## 访问配额消耗计算 {#visit-limits}

设定访问上限后，仅有效计入统计的请求会扣减额度，爬虫与预览不消耗次数。额度耗尽后，所有后续请求（包括本不计数的请求）均响应 410 状态页。

单实例通过共享原子计数器与缓存置换机制控制并发额度。需注意：爬虫判定依赖易伪造的请求头，访问上限属于业务统计配额而非高防鉴权，不可用于保护敏感机密。此外，禁止多个写入实例挂载同一个数据目录。

对文本分享而言，访问页面与拉取原始文本各算一次消耗：配额设为 1 的文本在页面阅读后，再次点击“原始文本”将返回 410。配额设为 3 的文件最多提供 3 次下载；当并发下载数达到 32 个时，新下载请求将直接被 503 拒绝，不占用剩余配额。

## 统计实时性与数据一致性

点击首先在内存中高效累加，通常每 2 秒合并写入数据库。总点击数直接读取活跃计数器或已提交的数据库快照，杜绝重复计算；列表缩略走势、每日统计、来源及最后访问时间直接读取已提交数据，可能存在秒级延迟。查看详情、大盘概览及导出数据时会主动触发刷盘；若写入遇阻将记录日志并返回当前旧值。并发场景下，各接口查询结果不保证属于绝对同一瞬间。

服务正常退出时会尝试在限时内清空积压写入，失败将以非零状态码告警。持续写入失败后强杀进程将丢失在途点击；突发断电还可能影响 SQLite WAL/NORMAL 模式下刚提交的事务。2 秒为正常调度间隔，并非持久性保证。详见[运维](./operations)。

## 时区约定

“今日”与每日聚合均依据 Sani 进程所设时区（环境变量 `TZ`）切分自然日。Docker 镜像未设 `TZ` 时默认采用 UTC，生产部署请根据需要配置（如 `TZ=Asia/Shanghai`）。

数据库内部持久化存储日期字串而非时间戳。变更 `TZ` 后，历史已有统计数据保持不变，新增点击将依新时区归档。

## 来源域名处理

- `Referer` 由客户端浏览器发送且允许伪造。为防止虚假来源导致数据库膨胀，每条链接上限存储 200 个独立来源域名，超出部分自动归并在“其他来源”。
- 部分浏览器或环境出于隐私策略默认抹除 Referer，HTTPS 降级至 HTTP 时亦不传递，故“直接访问”占比较高属于正常现象。
- 详情面板展示 Top 8 来源。占比基数为记录过来源的点击总量（导入的历史点击缺少来源数据，不计入分母）。

## 点击数低于预期的排查方向

- **永久跳转的本地缓存**：未设有效期或访问上限的 301/308 重定向允许浏览器缓存 1 天，期间该客户端再次访问不再回源。v0.8.0 起，带这些限制的跳转发送 `no-store`，但不能撤回此前已缓存的响应。需要精确计数的链接请采用默认的 302，并[绕过 CDN 动态缓存](./deploy#cdn-cache)。
- **自动预览过滤**：社交软件或聊天工具在输入链接时自动生成的抓取预览会被系统过滤。
- **管理后台自身点击**：在后台管理面板中点击链接测试不会增加计数。

## 为什么不做更复杂的统计

收集地域分布、设备型号、浏览器版本、UTM 链路等需要精细化采集单次访问链路，这不仅会让 Sani 演变为庞大的访客追踪系统，还会让数据库体积急剧膨胀。Sani 坚持极简纯粹。若需要全链路追踪，建议在目标站点部署专业分析 SDK：短链接会自动将 `utm_*` 等查询参数完整透传至目标页面。
