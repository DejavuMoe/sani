# 安全

<p class="lead">Sani 放在公网上，却只有一个主人。安全设计有两个出发点：没有密码或令牌的人什么都做不了；即使有人拿到了权限，也不能借 Sani 去攻击访问者，或者探测你服务器所在的内网。</p>

## 首次设置 {#setup}

一个刚启动、还没有密码的实例，如果谁先打开谁就能设置密码，那么在你打开它之前的那段时间，它就是不设防的。所以 Sani 要求首次设置时同时提供**设置码**：

- 设置码在每次启动时随机生成，只写在服务器日志里，能看到日志的人才能完成设置；
- 日志里附带的设置链接把设置码放在 `#` 后面，浏览器不会把这部分发给服务器，所以它不会出现在反向代理或其他任何访问日志里；
- 设置码填错按登录失败计算，同样受到限流；
- 设置只能成功一次，之后再请求会被拒绝。写入密码是一个原子操作，两个请求同时到达也只有一个能成功。

## 密码与会话 {#sessions}

- **密码**用 argon2id 哈希保存，参数采用 OWASP 的推荐值（2 次迭代、19 MiB 内存、1 个线程）。同一时间最多计算 2 个哈希，避免大量登录请求耗尽内存。
- **登录限流**按客户端地址计算：15 分钟内失败 8 次，就要等这 15 分钟过去才能再试。限流最多记录 10,000 个地址，不会被大量伪造的地址撑爆内存。
- **会话凭据**是 256 位的随机数，数据库里只保存它的 SHA-256 哈希，即使数据库泄露，也无法用它登录。
- **会话 Cookie** 带有 `HttpOnly` 和 `SameSite=Strict`，只发送给 `/api/` 下的地址，通过 HTTPS 访问时带 `Secure`。有效期 30 天，每天第一次使用时续期。
- **修改密码**会让其他设备全部退出登录；`sani passwd` 会让所有设备退出登录。

## API 令牌 {#tokens}

令牌形如 `sani_` 加 43 个随机字符（约 256 位），数据库里只保存哈希，明文只在创建时显示一次。令牌拥有完整权限，并且不受修改密码的影响，这样脚本不会因为你改了密码而失效；反过来，令牌泄露时要单独撤销。

## 跨站请求 {#cross-origin}

所有 `/api/` 请求都经过 Go 标准库的 `http.CrossOriginProtection`：浏览器从其他网站发起的请求会带上 `Sec-Fetch-Site` 或 `Origin` 请求头，据此被拒绝。再加上 `SameSite=Strict` 的会话 Cookie，别的网站无法冒用你的登录状态。脚本和命令行工具不发送这些请求头，使用令牌调用不受影响。

## 管理界面 {#admin}

管理界面的页面带有严格的内容安全策略：

- 脚本只能来自本站，唯一的内联脚本（在页面渲染前应用主题，避免闪烁）按哈希放行，哈希在启动时从页面内容计算；
- 不允许插件，不允许被其他网站嵌入（`frame-ancestors 'none'`），`<base>` 和表单提交目标也被限制；
- 另外带有 `X-Frame-Options: DENY`、`Referrer-Policy: same-origin`、`X-Content-Type-Options: nosniff`，并禁用摄像头、麦克风和定位权限。

管理界面不加载任何第三方资源，字体和图标都打包在程序里。

## 目标网址 {#destinations}

- **危险的网址类型**被拒绝：`javascript:`、`vbscript:`、`data:`、`file:`、`blob:`、`about:`、`filesystem:`、`view-source:`、`jar:`、`chrome:`、`chrome-extension:`、`moz-extension:` 和 `resource:`。
- **不能指向本站的短链接**，避免跳转循环，也避免用一串短链接隐藏真正的目标。
- **`Location` 响应头**中的非 ASCII 字符都会被编码：国际化域名转换为 Punycode，其余字符按百分号编码。换行等控制字符在保存网址时就被去掉了，无法注入额外的响应头。用百分号编码书写的域名会被拒绝，因为它会掩盖真实的目标。

## 抓取标题和图标 {#fetching}

服务端替用户访问任意网址，是 SSRF（服务端请求伪造）的典型入口：有人可以创建一条指向 `http://169.254.169.254/` 或 `http://192.168.1.1/` 的链接，让服务器去访问云平台的元数据接口或者内网设备。Sani 的抓取器分两道关卡防范：

1. **请求之前**：只允许 `http` 和 `https`；拒绝 `localhost`、不带点的主机名，以及 `.localhost`、`.local`、`.internal`、`.lan`、`.home.arpa` 结尾的域名；解析域名，只要有一个地址不是公网地址就拒绝。
2. **建立连接时**：拨号器在连接前再检查一次实际连接的 IP。这样即使域名第二次解析时换成了内网地址（DNS 重绑定），也连不上。

不被视为公网的地址包括：回环地址、私有网段、链路本地地址（包括云平台的元数据地址）、运营商级 NAT（`100.64.0.0/10`）、组播、文档示例网段、`240.0.0.0/4`、NAT64 和 6to4 等转换前缀，以及 Azure 的主机服务地址 `168.63.129.16`。`198.18.0.0/15` 是刻意放行的：以 fake-ip 模式工作的透明代理会把所有域名解析到这个网段。

其他限制：

- 每一次跳转都重新检查目标地址，最多跟随 5 次跳转；
- 网页最多读取 1 MB，图标最多 256 KB，单次请求 12 秒超时，每条链接的抓取总共不超过 20 秒；
- 最多 3 个抓取同时进行，大批量创建链接不会耗尽服务器的出站连接；
- 配置了 `HTTPS_PROXY` 时，代理本身的地址允许是内网地址；服务器无法解析的域名交给代理处理；
- 抓取请求带有 `X-Sani-Preview` 请求头，如果目标恰好是另一个 Sani 实例的短链接，不会被计为点击。

抓取到的图标来自第三方网站，Sani 按文件内容判断它是不是图片，返回时带上 `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox` 和 `nosniff`。即使有人直接打开一个 SVG 图标，其中的脚本也不会执行。

## 不受信任的输入都有上限 {#limits}

任何可以由外部控制大小的东西，都有明确的上限：

| 输入 | 上限 |
|---|---|
| 请求头 | 32 KB，5 秒内读完 |
| 整个请求 | 读写各 60 秒，空闲连接 120 秒 |
| JSON 请求体 | 1 MB |
| 导入的文件 | 32 MB，100,000 条链接 |
| 目标网址 | 8,192 字节 |
| 短码 | 64 个字符 |
| 标题 | 300 个字符 |
| 密码 | 1,024 字节 |
| 令牌名称 | 60 个字符 |
| 每条链接的来源网站 | 200 个；两次写入之间，内存里每条链接最多新增 64 个 |
| 登录限流记录的地址 | 10,000 个 |
| 不存在的短码的缓存 | `SANI_CACHE_SIZE` 的四分之一 |
| 抓取的网页和图标 | 1 MB 和 256 KB |

## 访问者的隐私 {#privacy}

Sani 不保存访问者的 IP 地址和 User-Agent，不设置 Cookie，只保存聚合后的计数，详见[统计口径](../guide/statistics)。访问者看到的 404 和 410 页面不加载任何外部资源，带有禁止一切脚本的内容安全策略，并告诉搜索引擎不要收录。

## 发布的文件 {#releases}

镜像和二进制文件都由 GitHub Actions 从打了标签的提交构建，不经过任何人的电脑：

- **校验和**：每个版本附带 `SHA256SUMS`，覆盖全部压缩包。
- **构建来源证明**：压缩包和镜像都有 GitHub 签发的来源证明，记录它是由哪个仓库、哪个提交、哪个工作流构建的。用 `gh attestation verify` 就能核对，方法见[部署](../guide/deploy#verify)。镜像还附带 SBOM，列出了其中的全部依赖。
- **可复现**：同一个提交构建两次，得到的压缩包逐字节相同。
- **依赖更新**：Dependabot 定期提出依赖更新，CI 每周用 `govulncheck` 检查一次已知漏洞。

## 报告安全问题 {#reporting}

发现安全问题时，请不要公开提交 issue，而是通过 GitHub 的 [私密漏洞报告](https://github.com/DejavuMoe/sani/security/advisories/new) 告诉我们。
