# 安全

<p class="lead">Sani 直面公网部署，由单一管理员掌控。核心安全防线：未获授权无法执行任何特权操作；即便获取权限，亦无法以 Sani 为跳板实施访客攻击或探测内网基础设施。</p>

## 首次设置安全校验 {#setup}

新启动且未配置密码的实例若允许任意首访者初始化，在初次访问窗口期极易失控。Sani 引入宿主绑定的**设置码**校验机制：

- 每次冷启动动态生成高熵设置码并写入服务日志，仅拥有宿主机访问权限的操作者可见；
- 启动日志中的引导链接将设置码置于 URL Hash（`#` 之后），浏览器不会将 Hash 发送至服务端，杜绝反代访问日志泄漏；
- 提交错误的设置码视作登录失败并纳入统一频控限流；
- 密码初始化具备单次原子生效特性，并发请求至多成功一个。

## 密码算法与会话安全 {#sessions}

- **密码哈希**：基于 argon2id 算法存储，选用 OWASP 权威推荐基准（2 次迭代、19 MiB 内存、单线程）。哈希运算全局最大并发为 2，防止高频暴力攻击耗尽系统内存。
- **IP 登录频控**：基于客户端来源 IP 进行滑动窗口限制（15 分钟内失败 8 次则暂时封锁）。限流表设置 10,000 个 IP 容量上限，杜绝伪造来源 IP 造成内存耗尽。
- **会话凭据**：生成 256 位加密安全随机串，数据库仅持久化其 SHA-256 哈希值，即便数据库意外泄露亦无法还原可用 Session。
- **会话 Cookie**：注入 `HttpOnly` 与 `SameSite=Strict`，严格限定作用域为 `/api/` 路径，HTTPS 环境自动强制 `Secure`。默认有效期 30 天，每日首访自动续期。
- **会话撤销**：前台修改密码自动注销其他已登录设备；运行 `sani passwd` 强制注销所有设备会话。

## API 令牌控制 {#tokens}

API 令牌形如 `sani_` 拼接 43 个随机高熵字符（约 256 位熵）。数据库仅保存 SHA-256 哈希值，明文仅在创建时单次展示。令牌具备完整管理员权限且不受改密影响，确保自动化脚本不间断；若有泄漏可在后台单项撤销。

## 跨站请求防御（CSRF） {#cross-origin}

所有 `/api/` 路由接入 Go 标准库 `http.CrossOriginProtection`：自动核查现代浏览器发起的 `Sec-Fetch-Site` 与 `Origin` 标头，拦截一切跨站写请求。结合 `SameSite=Strict` Cookie 隔离，彻底杜绝 CSRF。无标头的脚本与 CLI 凭令牌正常通行。

## 管理后台沙箱与 CSP {#admin}

管理端单页应用配置严格的 Content Security Policy（CSP）：

- 仅放行同源静态脚本，唯一的防闪烁内联脚本基于编译期计算的哈希白名单放行；
- 禁用浏览器插件，禁止第三方页面嵌入（`frame-ancestors 'none'`），锁定 `<base>` 与表单提交；
- 额外注入 `X-Frame-Options: DENY`、`Referrer-Policy: same-origin`、`X-Content-Type-Options: nosniff`，并全面封禁摄像头、麦克风与地理位置权限。

管理后台零外链加载，字体与 SVG 图标均已内嵌。

## 目标网址与重定向安全 {#destinations}

- **高危协议拦截**：拦截 `javascript:`、`vbscript:`、`data:`、`file:`、`blob:`、`about:`、`filesystem:`、`view-source:`、`jar:`、`chrome:`、`chrome-extension:`、`moz-extension:` 及 `resource:`。
- **防自引与循环跳转**：禁止短链接重定向至本站自身，防止循环跳转或套壳伪装。
- **响应头安全编码**：`Location` 响应头中的非 ASCII 字符全部规范编码（国际化域名转 Punycode，Path 按百分号转义）。换行等控制字符在入库时清洗，杜绝响应头注入（CRLF Injection）。禁止以百分号编码形式提交域名。

## 文本与文件分享隔离 {#shares}

[分享的文件内容](../guide/usage#shares)可能包含恶意 HTML 或嵌入脚本的 SVG，Sani 强制将分享内容与主站实行隔离：

- **强制独立文件域名**：原始文本流与文件下载必须通过[独立文件域名](../reference/configuration#sani-files-url)传输。会话 Cookie 严格限定于短链接主域且收敛于 `/api/`，文件域名绝无法获取 Cookie；文件域名亦不暴露管理端与 API。两者必须为主机名隔离的不同域（跨端口仍共享 Cookie，仅换端口会被系统拦截）。
- **下载安全响应头**：文件域名响应附带严格 CSP：`default-src 'none'; sandbox`、`X-Content-Type-Options: nosniff`、`Cross-Origin-Resource-Policy: same-origin` 与 `X-Frame-Options: DENY`。文件强制以附件形式下载（`attachment`），文本流标记为 `text/plain`。即便在浏览器标签页打开亦被沙箱阻断执行。
- **模板安全转义**：短链主域下的 `/p/{slug}` 引导页通过 Go `html/template` 安全转义，不渲染富文本，无外部依赖。
- **写操作鉴权**：创建分享必须具备管理员身份，访客无上传权限。
- **防暴力遍历短码**：分享短码采用 31 字符集的 10 位随机编码（空间达 8 × 10¹⁴），防范扫描枚举；`robots.txt` 全局拒爬 `/p/` 与文件域名。
- **底层文件存储安全**：上传文件先流式写入 `files/` 临时区，完成后转为随机 128 位物理文件名；原始文件名只留存数据库并剔除路径与控制字符。读取时严格校验随机映射名，杜绝目录穿越。孤儿文件每 10 分钟自动清理。

## 元数据抓取与 SSRF 深度防御 {#fetching}

服务端替用户访问任意外部网址，是 SSRF（服务端请求伪造）的典型入口。Sani 构筑了双重网络校验屏障：

1. **请求前静态过滤**：仅限 `http` 与 `https`；拒收 `localhost`、无点主机名及以 `.localhost`、`.local`、`.internal`、`.lan`、`.home.arpa` 结尾的内部域名；预解析域名，若任一解析 IP 命中私网则立即阻断。
2. **连接时拨号拦截**：定制网络拨号器，在实际握手建连的瞬间再次二次校验目标 IP，彻底粉碎基于 DNS 重绑定（DNS Rebinding）的绕过攻击。

非公网地址阻断范围涵盖：环回地址、私网 RFC 1918 网段、链路本地 Link-Local（含云厂商元数据接口 `169.254.169.254`）、运营商 CGNAT（`100.64.0.0/10`）、组播、测试保留网段、`240.0.0.0/4`、NAT64/6to4 映射地址及 Azure 服务地址 `168.63.129.16`。`198.18.0.0/15` 特意放行以兼容 fake-ip 透明网关。

其他抓取限制：

- 每次 30x 跳转均重新执行全量地址安全性校验，最大重定向次数为 5；
- 网页上限读取 1 MB，图标上限 256 KB，单请求超时 12 秒，全局单任务上限 20 秒；
- 抓取并发限制为 3，防止批量创建链接打满宿主机网络连接池；
- 配置 `HTTPS_PROXY` 时允许代理为内网地址，由代理执行远端解析；
- 抓取请求附加 `X-Sani-Preview`，避免嵌套请求污染目标 Sani 计数。

外部网站提取的图标进行文件头 Magic Number 校验，响应附加 `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox` 与 `nosniff`，阻断 SVG 内部脚本执行。

## 不信任输入规格上限 {#limits}

所有外部输入均施加严格的边界配额：

| 输入 | 上限 |
|---|---|
| 请求头 | 32 KB，5 秒内读完 |
| 整个请求 | 读写各 60 秒，空闲连接 120 秒；上传和下载为 1 分钟加上 64 KB/s 的连接所需的时间 |
| JSON 请求体 | 1 MB；创建和修改链接时 8 MB |
| 导入的文件 | 32 MB，100,000 条链接 |
| 文本 | 1 MB |
| 文件 | `SANI_MAX_FILE_MB`，默认 64 MB；上传时的其他字段各 4 KB |
| 文件名 | 255 字节 |
| 同时进行的下载 | 32 个 |
| 目标网址 | 8,192 字节 |
| 短码 | 64 个字符 |
| 标题 | 300 个字符 |
| 密码 | 1,024 字节 |
| 令牌名称 | 60 个字符 |
| 每条链接的来源网站 | 200 个；两次写入之间，内存里每条链接最多新增 64 个 |
| 登录限流记录的地址 | 10,000 个 |
| 不存在的短码的缓存 | `SANI_CACHE_SIZE` 的四分之一 |
| 抓取的网页和图标 | 1 MB 和 256 KB |

## 访客隐私策略 {#privacy}

Sani 不保存访问者的 IP 地址和 User-Agent，不设置 Cookie，只保存聚合后的计数，详见[统计口径](../guide/statistics)。访问者看到的 404 和 410 页面不加载任何外部资源，带有禁止一切脚本的内容安全策略，并告诉搜索引擎不要收录。分享页面也一样，只多了一个复制用的脚本，而且不会把 `Referer` 传给下一站。

## 发布物与供应链安全 {#releases}

镜像和二进制文件均由 GitHub Actions 在打标提交上无干预构建：

- **完整性校验**：每个版本附带 `SHA256SUMS`，覆盖全部压缩包。
- **构建来源证明**：压缩包和镜像包含 GitHub 签发的数字来源证明，记录仓库、提交及工作流信息。可通过 `gh attestation verify` 快速验证（详见[部署验证](../guide/deploy#verify)）。镜像内嵌 SBOM 依赖清单。
- **确定性可复现构建**：同一源码提交在相同环境下构建出的压缩包逐字节一致。
- **依赖审计**：Dependabot 定期提交依赖更新，CI 每周用 `govulncheck` 扫描已知漏洞。

## 报告安全问题 {#reporting}

若发现安全隐患，请勿公开发布 issue，请通过 GitHub 的 [私密漏洞报告通道](https://github.com/DejavuMoe/sani/security/advisories/new) 提交。
