# 架构

<p class="lead">Sani 是一个 Go 进程：跳转、JSON API 和管理界面都由它提供，数据保存在一个 SQLite 文件里。整个结构围绕一个目标展开：跳转要快，而且不受其他任何操作的影响。</p>

## 路由

| 路径 | 处理方式 |
|---|---|
| `/` | 跳转到 `SANI_ROOT_REDIRECT`，默认是 `/admin/` |
| `/admin/…` | 内嵌的管理界面，一个单页应用 |
| `/api/…` | [JSON API](../reference/api) |
| `/p/…` | [分享的文本和文件](../guide/usage#shares)的页面 |
| `/healthz` | 健康检查，返回 `ok` |
| `/robots.txt` | 告诉搜索引擎不要抓取 `/admin/`、`/api/` 和 `/p/` |
| `/favicon.ico` 等 | 管理界面的图标 |
| 其他所有路径 | 短链接 |

发往[文件域名](../reference/configuration#sani-files-url)的请求在这一切之前就按主机名分开，只会到达返回分享内容的那个处理函数。

## 跳转的热路径

`internal/server/redirect.go` 处理 `/{slug}`，一次跳转依次经过：

1. **检查请求**：只接受 `GET` 和 `HEAD`。去掉末尾的 `/`，明显不可能是短码的路径直接返回 404，连缓存都不查。
2. **计算查找键**：Unicode 规范化（NFC）之后转为小写，所以 `/GitHub` 和 `/github`、不同输入法打出的同一个字都能对上。
3. **查缓存**：缓存分成 64 个分片，每个分片一把读写锁。命中时只是读锁下的一次 map 查找；已知不存在的短码也在缓存里，直接返回 404。
4. **缓存未命中**：从读连接池查一次数据库，结果写回缓存。同一个短码的并发未命中只查一次，其余请求等待这次查询的结果。如果查询期间有修改让缓存失效，这次结果照常返回，但不写回缓存，以免缓存住旧数据。
5. **检查状态**：是否停用、是否过期、访问次数是否用完。访问次数是缓存条目上的一个原子计数器。
6. **记一次点击**：[计入统计](../guide/statistics#counted)的请求把点击交给点击聚合器，只是一次内存累加，不等待任何写入。
7. **返回**：拼接查询参数，写入 `Location` 和 `Cache-Control`，返回跳转状态码。

404 和 410 页面在启动时按语言预先渲染好，并在短链接出现的位置切开，返回时只需要写三段字节。有人扫描大量随机路径时，这让出错页面几乎和跳转一样便宜。

## 点击的去向

`internal/clicks` 按链接 ID 把点击分到 32 个分片里，每条链接在内存中累计总数、最近一次访问的时间、每天的点击数和各来源的点击数。

每隔 2 秒，聚合器把所有分片的数据取出，合并成一批，在**一个事务**里写入 SQLite：更新 `links` 表的总数和最近访问时间，累加 `clicks_daily` 和 `referrers` 两张表。写入失败时，这批点击会放回内存，下一次再试。

从取出到写入完成的这段时间里，这些点击仍然计入 API 返回的数字，所以管理界面上的数字不会忽高忽低。服务停止时，HTTP 服务器先停止接受请求，然后写入最后一批点击。

## 数据库

SQLite 通过 [modernc.org/sqlite](https://gitlab.com/cznic/sqlite) 使用，这是纯 Go 实现，不需要 cgo，所以二进制文件可以静态链接，镜像可以基于 `scratch`。

- **WAL 模式**，读不会被写阻塞。
- **一个写连接**，所有写入排队进行，写入之间不会互相争抢锁；事务以 `BEGIN IMMEDIATE` 开始。
- **一组读连接**，数量为 CPU 核数，至少 4 个。

| 表 | 内容 |
|---|---|
| `links` | 每条链接：类型、短码和查找键、目标网址、标题、各项设置、总点击、最近访问时间、删除时间 |
| `contents` | 文本或文件分享的内容：文本的正文、格式和行数，或者文件的名称、类型、SHA-256 和保存时用的名称 |
| `clicks_daily` | 每条链接每天的点击数 |
| `referrers` | 每条链接每个来源网站的点击数，每条链接最多 200 个来源 |
| `settings` | 密码哈希、设置页里的短链接域名 |
| `sessions` | 登录会话，只保存凭据的哈希 |
| `tokens` | API 令牌，只保存哈希 |
| `favicons` | 抓取到的网站图标，按域名保存 |

分享的文件本身不在数据库里，而是以随机名称保存在数据目录下的 `files/` 中；文本和文件与链接共用缓存和点击计数。

数据库结构的版本记在 `PRAGMA user_version` 里，启动时按顺序执行还没执行过的升级，每一步都在事务里完成。

## 后台任务

| 任务 | 频率 | 做什么 |
|---|---|---|
| 写入点击 | 每 2 秒 | 把内存中的点击批量写入数据库 |
| 清理删除的链接 | 每分钟 | 彻底删除一小时前删除的链接和它们的统计 |
| 清理会话 | 每小时 | 删除已经过期的登录会话 |
| 清理文件 | 每 10 分钟 | 删除没有链接再引用的文件，以及没有传完的上传 |
| 抓取标题和图标 | 新建链接时 | 最多 3 个同时进行，每个最多 20 秒 |

## 标题与图标

新建链接后，后台任务访问目标网页，最多读取 1 MB，最多跟随 5 次跳转，请求会带上你浏览器的语言偏好，所以得到的标题通常是你习惯的语言。

- **标题**：依次取 `og:title`、`twitter:title` 和 `<title>`。目标是 PDF 这类文件时，用文件名作为标题。
- **图标**：从网页声明的图标里挑选，优先尺寸接近 64 像素的图片和 SVG，其次是 `apple-touch-icon` 和更大的图片，最后是 `/favicon.ico`，最多尝试 4 个。图标不超过 256 KB，并且要确认内容确实是图片。
- **复用**：图标按域名保存，同一个网站的其他链接直接复用。超过 30 天的图标会在下次用到时重新获取；获取失败的，一天之内不再重试。

抓取只会访问公网地址，详见[安全](./security#fetching)。

## 管理界面

管理界面用 Svelte 5 和 TypeScript 编写，由 Vite 构建，没有使用任何 UI 库或图标库。构建产物会预先压缩成 Brotli 和 gzip 两种格式，通过 Go 的 `embed` 打包进二进制文件，服务时按浏览器支持的编码直接返回压缩好的版本。

带哈希的文件名的静态资源缓存一年；`index.html` 每次都会重新验证，并带上严格的内容安全策略。
