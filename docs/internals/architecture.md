# 架构

<p class="lead">Sani 用单个 Go 进程提供短链跳转、JSON API、文本与文件分享及管理界面。SQLite 保存记录与文本，files/ 保存上传内容。缓存和异步统计让命中缓存的跳转不等待数据库写入；冷加载与资源竞争仍会影响延迟。</p>

## 路由拓扑

| 路由路径 | 对应处理逻辑 |
|---|---|
| `/` | 重定向至 `SANI_ROOT_REDIRECT`（缺省重定向到 `/admin/`） |
| `/admin/…` | 内嵌的管理后台单页应用（SPA） |
| `/api/…` | [JSON API](../reference/api) |
| `/p/…` | [文本与文件分享](../guide/usage#shares)引导页 |
| `/healthz` | 基础存活探针，返回 `ok` |
| `/robots.txt` | 爬虫防爬规则（阻断 `/admin/`、`/api/` 及 `/p/`） |
| `/favicon.ico` 等 | 静态站点图标 |
| 其他任意路径 | 短链接匹配与重定向引擎 |

绑定在[独立文件域名](../reference/configuration#sani-files-url)的流量在顶层依据 Host 隔离，直达底层分享流处理器。

## 跳转执行热路径

短链接请求（`/{slug}`）由 `internal/server/redirect.go` 接管，生命周期如下：

1. **协议校验与清洗**：仅允许 `GET` 与 `HEAD`。去除尾部斜杠，对明显非法短码直接快速返回 404，不触发缓存穿透。
2. **规范化键计算**：基于 Unicode NFC 规范化并转为小写。支持不区分大小写及统一输入法编码。
3. **分片缓存查询**：缓存水平切分为 64 个独立分片，各持专属读写锁。命中时仅耗费读锁下的一次哈希查找；对已知不存在的短码亦有负缓存机制，直接返回 404。
4. **缓存未命中回源**：从数据库读连接池加载，将库内已提交计数与内存活跃批次配对写入缓存。冷加载快照期间与刷盘协调，命中请求不等待刷盘。同短码、同缓存纪元的并发未命中共享一次查询。若查询期间缓存失效，已经开始的请求仍可使用旧结果，但不回填；失效后开始的新请求不会加入旧加载。
5. **状态与配额拦截**：核验启用状态、截止时间及剩余访问上限。同链接不同条目共享原子计数器，缓存置换不重置已消耗额度。
6. **内存递增统计**：[符合口径](../guide/statistics#counted)的有效访问投递给点击聚合器，仅执行纳秒级内存累加，无任何同步写库等待。
7. **响应输出**：合并查询参数，注入 `Location` 与 `Cache-Control` 头并响应重定向。

404 与 410 错误页按语言在启动时预渲染，响应时分段写出页面与短码。已缓存的不存在短码可直接返回；扫描新短码仍会触发数据库查询，负缓存不能代替入口流量限制。

## 点击数据流转机制

`internal/clicks` 依据链接 ID 将计数哈希至 32 个分片，在内存中汇聚总点击、最后访问时间戳、每日走势及来源域名明细。

聚合调度器每 2 秒汇总全部内存分片，在**单个数据库事务**中批量写入 SQLite：同步 `links` 表总量，并增量更新 `clicks_daily` 与 `referrers`。写入若偶发失败，当前批次将自动回滚保留在内存中等待下个周期重试。

总计数值取自同一原子计数器，避免将不同时间点的库内快照与提交批次交叉误算。大盘与每日走势直接读取库内已提交记录；计数器弱引用在对象回收时注销。每链接单批次最多记录 64 个新来源加“其他”，合并重试同样遵循该上限。停机顺序与持久性限制见[运维](../guide/operations)。

## 底层存储设计

数据库采用纯 Go 实现的 [modernc.org/sqlite](https://gitlab.com/cznic/sqlite)，彻底免除 cgo，使得应用能够静态编译交付且能在 `scratch` 基础镜像中裸跑：

- **WAL 日志模式**：允许普通读操作与写入并发，连接池和外部锁仍可能造成等待。配置 `synchronous=NORMAL`，断电持久性详见[运维](../guide/operations)。
- **单写连接池**：本进程的写入在一个连接上排队，以 `BEGIN IMMEDIATE` 开启事务，减少写锁竞争；外部写入者仍可能引发忙等待或错误。
- **并发读连接池**：连接上限为启动时的 `GOMAXPROCS`，至少 4 个。

核心数据表结构：

| 表名 | 职责 |
|---|---|
| `links` | 链接核心元数据：短码、规范查找键、目标 URL、标题、策略配置、总点击、最后访问时间、软删除时间 |
| `contents` | 文本与文件分享内容：文本正文/格式，或文件的 MIME、SHA-256 及实际存储文件名 |
| `tags` | 管理员标签的名称、规范化名称键与颜色 |
| `link_tags` | 链接与标签的关联及显示顺序，每条链接最多 5 个 |
| `clicks_daily` | 单链接按日聚合的点击走势 |
| `referrers` | 单链接来源站点分布（单链上限 200 个来源） |
| `settings` | 管理员密码哈希与持久化域名配置 |
| `sessions` | 登录会话凭据 SHA-256 哈希 |
| `tokens` | API 令牌 SHA-256 哈希 |
| `favicons` | 站点图标缓存，按域名持久化归档 |

分享文件以高熵随机名存放在数据目录 `files/` 中，数据库仅保留引用指针；文本与文件共享全局短链缓存与点击计数机制。

数据表版本受控于 `PRAGMA user_version`，服务启动时按顺序执行事务性迁移。schema 4 已新增 `tags`（名称、规范化名称键、颜色）与 `link_tags`（链接 ID、标签 ID、显示顺序），关联通过外键清理，按标签筛选有独立索引。schema 3 引入的 `AUTOINCREMENT` 继续保证链接 ID 不复用。标签分配与链接保存处于同一事务，跳转缓存与目标查询不读取标签。升级前请做好完整备份；降级需要恢复升级前备份。

## 后台异步调度

| 任务 | 调度周期 | 工作职责 |
|---|---|---|
| 点击批量刷盘 | 每 2 秒 | 将内存暂存的点击指标合并写入数据库 |
| 软删除数据清理 | 每 1 分钟 | 物理清理删除已超 1 小时的链接及关联统计 |
| 过期会话回收 | 每 1 小时 | 清除数据库中过期的管理员登录会话 |
| 孤儿文件清理 | 每 10 分钟 | 物理移除无短链引用的废弃文件及未完成上传 |
| 网页元数据抓取 | 链接创建触发 | 最大 3 并发，单任务硬超时 20 秒 |

上传请求并行持有文件生命周期读锁，直到数据库接管文件或失败清理完成。存在活跃上传时，本轮孤儿扫描跳过；因此持续上传会推迟孤儿回收。没有活跃上传时，扫描仍按文件年龄与数据库引用判断是否删除。

## 网页元数据与 Favicon 抓取

新建短链后，后台爬虫异步拉取目标页（最多读取 1 MB，最多跟随 5 次重定向），请求头透传客户端 Accept-Language，优先适配用户语言：

- **标题提取**：优先级依次为 `og:title` → `twitter:title` → `<title>`。针对静态文件（如 PDF）直接以文件名作为标题。
- **图标选择**：智能评估 HTML 中声明的 icon，优先选取接近 64px 的 PNG 或矢量 SVG，其次取 `apple-touch-icon`，最后尝试 `/favicon.ico`（单任务最多试探 4 个）。单图标大小上限 256 KB，严格校验图片 Magic Number。
- **域名级复用**：图标基于 Host 缓存复用，同域名短链无需重复抓取。缓存超 30 天自动刷新；探测失败的域名在 24 小时内免重试。

抓取器对目标主机和直接拨号地址执行私网检查；使用环境代理时，代理的 DNS 与转发策略属于运维信任边界，详见[安全机制](./security#fetching)。

## 管理界面架构

管理端基于 Svelte 5 (Runes) + TypeScript 开发，由 Vite 打包，未使用外部 UI 或图标库。产物在构建时预先生成 Brotli 与 gzip 压缩版本，通过 Go `embed` 注入二进制。运行时根据客户端 `Accept-Encoding` 选择响应，不再动态压缩。

带哈希的静态资源配置 1 年长期缓存；入口 `index.html` 每次协商验证并附带严苛的内容安全策略（CSP）。

Schema 5 重建标签表，接受规范化六位 HEX 与旧命名色，保留 ID 和链接关联。创建默认值复用 settings 表。升级前备份；v0.8.x 无法打开 schema 5，降级须恢复升级前的数据库与分享文件。

schema 6 追加 `contents.delete_key` 与非空唯一索引，为既有文件生成随机密钥，不改写资源或公开路径。`/api/v1` 与 `/api/admin/v1` 共享输入校验、创建/更新、流式上传、SQLite 和缓存失效；兼容层校验单个已配置域名，保留原有全局短码空间。
