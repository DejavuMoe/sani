# 版本与兼容

<p class="lead">升级 Sani 时，既有短链接、自动化脚本与环境配置是否稳定可用？本页说明语义化版本规则、兼容性承诺范围，以及 1.0 正式版前后的演进边界。</p>

## 版本语义准则 {#semver}

Sani 严格遵循[语义化版本 2.0.0](https://semver.org/lang/zh-CN/)（`主版本.次版本.修订版本`）：

- **修订版本**（如 0.1.0 → 0.1.1）：仅包含 Bug 修复，升级前建议查阅更新日志并备份；
- **次版本**（如 1.1 → 1.2）：向后兼容的功能新增；
- **主版本**（如 1.x → 2.0）：允许包含破坏性变更，[更新日志](./changelog)将给出详细迁移指南。

**在 1.0 之前（0.x 阶段）**，次版本升级（如 0.1 → 0.2）可能包含非向前兼容的调整。所有断代修改均在更新日志的“不兼容的修改”中清晰公示。1.0 正式发布后，下列兼容承诺将在整个主版本生命周期内严格兑现。

## 强兼容承诺范围 {#stable}

### 短链接路由行为

升级后既有短链接保持稳定：相同路径、相同状态码与目标 URL。系统保留保留字路径（如 `admin`、`api` 等，详见[日常使用](../guide/usage)）仅在主版本跨越时才可能扩充，杜绝既有业务短码意外失效。

### HTTP API

[HTTP API 规范](../reference/api)中声明的路由、参数、响应体及[错误码字典](../reference/api#errors)保持向后兼容。次版本更新仅允许：

- 扩展新增端点；
- 在响应中追加非破坏性字段；
- 在请求参数中引入可选字段（缺省保持既有逻辑）；
- 引入新增业务错误码。

调用方脚本应主动忽略未知响应字段，并将未识别的错误码作为常规错误兜底处理。错误体中的 `message` 属于诊断文案，程序逻辑应严格匹配 `code`。

### 环境变量配置

所有 `SANI_*` [环境变量](../reference/configuration)保持语义、命名与缺省值稳定。新配置项默认值均保证行为向前兼容。

### 命令行工具

所有[命令行子命令](../reference/cli)及其参数选项保持稳定。

### 数据存储与迁移

- **数据库向前迁移**：新版本平滑兼容同一主版本下的所有旧数据库，启动时自动执行无感迁移。注意旧版本二进制无法降级读取新结构，因此升级前请务必[执行备份](../guide/operations#backup)。
- **备份兼容性**：`sani backup` 导出标准 SQLite 数据库文件；包含文件分享的完整恢复还需搭配同次停机导出的 `files/`（详见[配套备份](../guide/operations#backup-files)）。
- **导入导出格式**：系统导出的 JSON 与 CSV 永久支持在后续版本中导入。JSON 元数据中的 `"version": 1` 标识数据格式版本。

### 制品分发标识

镜像坐标 `ghcr.io/dejavumoe/sani`、Tag 命名策略及预编译归档包名称（参见[部署说明](../guide/deploy#binaries)）保持固定，便于部署脚本长期锚定。

## 非兼容承诺范围（内部实现） {#unstable}

- **管理前端界面**：UI 视觉呈现、操作交互与辅助快捷键可能持续优化。
- **运行日志细节**：标准输出日志格式与文案可能微调（首次设置的 `setup_code` 提取逻辑除外）。
- **数据库内部 Schema**：内部数据表与索引结构保留演进自由度。数据交互请统一通过 API、导出工具或 `sani backup` 进行，切勿直接操作底层表。
- **基准测试数据**：性能数据反映特定硬件测量表现，不作为 SLA 指标承诺。
- **内部 Go 包**：`internal/` 目录下的代码为私有包，不对外暴露。

## 特性弃用周期 {#deprecation}

计划移除的特性会提前在更新日志与文档中标记为“已弃用”，并在当前主版本中保持正常可用，直至下一个主版本才会正式剔除。

## 1.0 正式发布验收准则 {#before-1}

在从 0.x 迈向 1.0 正式发布前，必须完成以下验收：

- 锁定对外 HTTP API、环境变量默认值、CLI 参数、保留路径及导出协议，双语参考文档与源码建立全自动核对断言。
- 验证历史各版本数据库表结构向后无缝迁移，确保网址、文本、文件、统计及会话完整保留；迁移失败需原子回滚，旧版程序必须显式拒绝新 schema；完成冷备恢复全链路演练。
- Linux、Windows、macOS 全量自动化测试通过；覆盖全平台二进制编译产物，完成 E2E、无障碍及依赖漏洞扫描；所有构建以 GitHub Actions 远程 CI 为发布依据。
- 建立可复现的容量基准，量化延迟、内存、锁争用与计数无损一致性。
- 对任何行为逻辑调整明确列出“不兼容的修改”并附升级步骤，且必须置于次版本中，禁止混入修订号补丁。

数据库内部表结构属于系统私有实现，1.0 之后仍保留按需迁移升级的自由度。
