## 评估到设计的对应

| 评估问题 | R7 决策及行为 | 场景 |
|---|---|---|
| 标签 Enter 误选模糊匹配 | 完整名称匹配优先；保留方向键选择、五个上限与输入法组合事件保护。示例故意让 devops 排在 dev 前 | dashboard → 标签 → 输入 dev → Enter |
| 缺少全局删除，局部关联与全局编辑混淆 | 列表与选择器都有“管理标签”；选择器只关联/移除当前内容。管理器搜索、未使用过滤、关联数量、全局编辑与删除 | tags、tags-error、delete-error |
| 删除影响不清楚 | 确认展示名称、跨链接/文本/文件的关联数；删除关联而保留内容及其他标签；只有成功才移除目录。删除当前筛选标签仅清除该标签条件 | delete-error：删除 netcup，首次失败，重试成功，文本类型仍保留 |
| 标签很多时占满界面 | 少量常用标签 + 更多标签搜索；移动端收缩但当前选中项始终可见 | dashboard |
| 提交成功清掉新输入 | 采用较小的方案：提交期间锁定该表单字段；成功后重置提交的草稿，失败保留；上传可取消 | dashboard + latency=3000、create-error、file-create |
| 离开编辑丢草稿 | Escape、取消、进入设置、切换列表上下文经过同一守卫；继续编辑 / 放弃修改 / 保存并离开。保存失败仍留编辑器与草稿 | edit、edit-error |
| 刷新回到 50 条并丢失多选 | 同一查询的刷新保持加载范围、展开与选择；分页错误独立，已加载内容仍可操作 | refresh-error、page-error |
| 筛选失败却显示旧列表为新结果 | 明确失败提示，旧结果暂时不可操作；原处重试后显示当前查询结果 | query-error：输入搜索词触发首次失败 |
| 统计失败等同 0 | 首次失败显示未知；切换范围失败保留旧图并说明实际旧范围 | stats-error、stats-stale |
| 令牌加载失败等同无令牌 | 失败显示未知数量并重试；确认加载成功前禁用创建；真正无令牌使用独立空状态 | tokens-error、tokens-empty |
| 三类命名与统计口径不清楚 | 顶部改为“链接 / 文本 / 文件”；网址输入仍称“网址”；摘要“内容总数 / 总访问 / 今日访问”，明确覆盖全部未删除内容、标签数包含停用/过期、访问不是人数 | dashboard |
| 空状态缺少具体出路 | 无数据、未使用标签、组合筛选无结果分别说明原因；定向清除标签或类型条件 | empty、empty-tag、empty-combined |
| 创建后筛选变化不明 | 创建成功并清除筛选时提供反馈；更多选项显示已设数量 | dashboard |
| 访问次数、过期、301 边界 | 次数说明随内容类型变化；文本页与 raw 分别消耗次数；到期停止访问但保留内容；301 明示缓存影响 | text-create、创建/详情内访问规则 |
| 导出与备份混淆 | “导出网址链接”；明确不包含文本/文件；完整备份链接至现有运维文档，不新增后台一键备份承诺 | import / 设置 |
| 导入明细只看得到前 20 条 | 显示总数、前 20 条预览，提供全部跳过记录 JSON 下载（示例 27 条） | import |
| 文件分享未启用无出路 | 解释不可用并提供现有配置文档入口 | files-off |

场景标识统一前缀 `r7-`。选择器、颜色编辑、菜单均复用已有自定义控件；未引入浏览器原生 select/color/date 控件。

## 推荐审阅顺序

1. 打开标签管理，查看 netcup 的 5 条关联及未使用标签。编辑任一名称/颜色；试删 netcup，检查确认内容。再进入“删除失败与重试”查看失败恢复。
2. 打开慢请求创建，填写网址并提交，检查所有字段锁定；另看上传过程中取消能保留文件草稿。
3. 文本编辑中修改正文，按 Escape 或进入设置；分别检查继续编辑、放弃和保存。保存失败场景应保留修改。
4. 分页失败场景先加载更多，再重试；刷新失败场景先加载到 69 条，再重试刷新，确认已选 1 条不变。
5. 检查令牌读取失败、统计切换失败和组合筛选空结果，区分“未知”“旧数据”“确实为空”。
6. 下载完整跳过明细；查看一次访问文本的提示。最后切换 English / Dark，并在窄屏打开管理器和子确认框。

## 实施交接与暂缓项

本原型决定交互契约，不证明生产缺陷已修复。批准后应沿当前 Svelte store、TagPicker、Links/详情/设置组件与 Go API 实施，不能复制 React mock 或将 designs 作为运行依赖。

- 全局标签删除必须在数据库事务中处理目录及关联；校验当前引用数量与并发删除结果，成功后同步筛选、编辑草稿、选中集合。具体 HTTP 接口与错误码需按现有接口设计，并同步中英文 API 文档。
- 列表需区分查询切换、同查询刷新和下一页，阻止迟到响应覆盖当前查询；真实数据下按 ID 协调删除、过滤变化和选择。跨标签页更新及超过 50 条的并发一致性属于工程验收。
- 锁定创建表单是本轮方案；不引入草稿版本号、多草稿队列或自动本地持久化。真实创建成功与剪贴板失败要继续区分。
- 离开守卫覆盖原型内导航。关闭浏览器/刷新页面的 `beforeunload` 行为、输入法真实键盘和 assistive technology 需生产实现时验证，不能用自定义弹窗承诺浏览器生命周期行为。
- 完整导入错误下载需绑定真实响应，不能只导出 UI 截断的前 20 条。下载内容及文件名仍需实施时审查。
- **暂缓而非遗漏**：服务端状态过滤、旧短码保留策略、最后一次访问后 raw/download 的产品语义调整、运营可观测性。这些分别涉及查询能力、兼容性、访问计数策略与服务运维，不由本轮管理界面擅自改变。当前访问规则只解释已有行为。
- 不引入标签层级、多用户、复杂统计、新备份服务或未批准的 R4 配置方向。

用户可直接对 R7 的入口、删除确认文案、锁定表单方案、离开编辑的三项选择以及错误状态提出修改；`_d_meta.json` 中 R7 已由用户批准为 `approved`。
